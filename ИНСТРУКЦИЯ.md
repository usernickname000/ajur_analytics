# Инструкция по работе с аналитикой заказов

Документ описывает как программа считает выручку, откуда берутся данные,
как сверяться с бухгалтерией и что менять при переходе на новый год.

Это разбор методологии и runbook. Справочник по фичам/файлам/листам
отчёта — в `README.md`.

---

## 1. Откуда берутся цифры в отчёте

Программа работает с **двумя источниками данных**:

### Источник 1 — CRM (Битрикс)
Выгрузка заказов `заказы_YYYYг._обновлено_DD.MM.YYYYг.xlsx`. Это основа.
Из неё считаются **все разрезы**: клиенты, менеджеры, отрасли, RFM, номенклатура, сезонность.

### Источник 2 — `external_income.json`
Внешние доходы, которых нет в CRM: программатик (~119 млн/год), бартер,
гранты, ИРИ, взаимозачёты. Заполняется двумя способами:
- **автоматически** — импортом мастер-файла бухгалтерии «Доходы ГГГГ.xlsx»
  через `dohody_import.py` (см. §5);
- **вручную** — через GUI **⚙ Внешние доходы**, если нужна точечная правка.

Эти данные попадают только в **сводные цифры** (общий итог, по месяцам,
по кварталам, по сезонам). В разрезы клиентов/менеджеров/отраслей они
не добавляются — там нет информации откуда к какому клиенту отнести сумму.

## 2. Что показывает лист `01_Месячная_статистика`

В месячной таблице — **пять разных сумм выручки**:

| Колонка | Что считает | Когда использовать |
|---|---|---|
| Сумма выручки, тыс. руб. (CRM, дата заказа) | Только CRM, группировка по дате заказа | Внутренний анализ продаж |
| Выручка по дате оплаты, тыс. руб. | Только CRM, но по дате оплаты | **Сверка с бухгалтерией** |
| Внешние доходы, тыс. руб. | Программатик и др. из `external_income.json` | — (служебная) |
| Итого с внешними, тыс. руб. | CRM (дата заказа) + внешние | Для презентации — "как было" |
| **Итого по оплате + внешние, тыс. руб.** | CRM (дата оплаты) + внешние | **Главная цифра для презентации** |

Переключатель «дата заказа / дата оплаты» для всего отчёта (в т.ч. топов
клиентов/менеджеров) — на вкладке Анализ, «Дата для группировки».

### Какую колонку использовать в презентации

Для максимального совпадения с верифицированными цифрами бухгалтерии —
**«Итого по оплате + внешние»**. Даёт погрешность около 1%.

## 3. Верифицированные цифры года (`verified_figures.json`)

Годовые итоги из отчёта бухгалтерии, с которыми сверяется CRM. Хранятся
**не в коде**, а в `verified_figures.json`, редактируются через GUI
**⚙ Верифицированные цифры**. На 2025 год:

| Поле | Значение (2025) |
|------|------------------|
| `total_with_prog` — всего с программатиком и бартером | 482 404 000 |
| `total_with_barter_no_prog` — с бартером, без программатика | 363 000 166 |
| `advertising_no_events` — рекламная без мероприятий | 243 005 820 |
| `programmatic_external` — программатик внешний (итог) | 119 403 897 |
| `other_external_income` — прочие внешние (ИРИ, гранты, 47) | 41 057 102 |

В `analytics.py` есть одноимённые константы (`VERIFIED_TOTAL_WITH_PROG` и
т.д.) — это **fallback на случай отсутствия файла**, их трогать не нужно.
Источник истины — JSON.

## 4. Как программа считает выручку: три варианта

### Вариант А — по дате заказа
Группировка по колонке «Месяц» из CRM = месяц, к которому заказ был
отнесён менеджером при создании.

**Плюс:** вся выручка периода попадает в отчёт за этот период.
**Минус:** не бьётся с бухгалтерией на уровне каждого месяца.

### Вариант Б — по дате оплаты
Группировка по `ДатаСуммаОплаты_`.

**Плюс:** бьётся с бухгалтерией с погрешностью ~1%.
**Минус:** заказы, оплаченные после конца года, уезжают в следующий год.

### Вариант В — CRM + внешние доходы (то что нужно для презентации)
Вариант Б + данные из `external_income.json`. На 2025 год давал 477 491
тыс. против цели бухгалтерии 482 404 тыс. — разница около 1%.

## 5. Как обновлять `external_income.json`

### Способ 1 — импорт мастер-файла бухгалтерии (по умолчанию)
`dohody_import.py` читает лист `ДОХОДЫ ГГГГ` файла «Доходы ГГГГ.xlsx» и
сам обновляет JSON — пишет только статьи, которых нет в CRM, сверяет
сумму с итоговыми строками файла, подсвечивает выбросы по месяцам.

GUI: **⚙ Импорт Доходы.xlsx** (сначала отчёт, запись — по «Применить»).
Консоль:
```bash
python dohody_import.py "Доходы 2026.xlsx"          # отчёт, без записи
python dohody_import.py "Доходы 2026.xlsx" --apply   # применить
```

### Способ 2 — ручная правка
GUI **⚙ Внешние доходы** — таблица 12 месяцев × статьи, с сохранением в
JSON. Нужна, если бухгалтерия прислала цифру без обновления всего файла,
или для строк, которых нет в мастер-файле.

Формат (если открываешь JSON руками — цифры **в рублях, не в тысячах**):
```json
"Программатик ФОНТАНКА": {
  "01": 4611923.68, "02": 4943308.41, ... "12": 8767835.58
}
```

### Служебный ключ `_включать_в_аналитику`
Список строк, которые прибавляются к CRM при расчёте «Внешние доходы» в
месячной/сезонной/квартальной аналитике. Сейчас — только программатик:
```json
"_включать_в_аналитику": [
  "Программатик ФОНТАНКА", "Программатик ФОНТАНКА ТГ",
  "Программатик ДОКТОР", "Программатик ДОКТОР ТГ"
]
```
Бартер туда обычно не добавляют — это внутренний зачёт, а не реальная
выручка от клиента.

## 6. Переход на новый год (например, на 2026)

1. **Импортировать новый мастер-файл.** GUI **⚙ Импорт Доходы.xlsx** →
   выбрать «Доходы 2026.xlsx» → посмотреть отчёт (сверка сумм, выбросы,
   несопоставленные строки) → «Применить». `_год` в `external_income.json`
   переключится на 2026, старый файл уйдёт в
   `external_income_2025_backup.json`.
2. **Проверить несопоставленные строки** в отчёте импорта. Если
   бухгалтерия переименовала или добавила статью — дополнить
   `RAW_LABEL_MAP` в начале `dohody_import.py` (и, если статья новая,
   `ACCOUNTING_ROWS`/`ACCOUNTING_BLOCKS` в `analytics.py`).
3. **Обновить верифицированные цифры.** Когда бухгалтерия закроет год и
   пришлёт итоговый отчёт — GUI **⚙ Верифицированные цифры**, вписать
   5 полей за 2026 год (см. §3). Это не автоматизировано намеренно —
   цифра должна быть подтверждена бухгалтерией, а не посчитана программой.
4. **Проверить маппинг проектов.** Если в CRM появились **новые проекты**
   (например, «Фонтанка.ру: Подкасты») — добавь их в `PROJECT_GROUP_MAP`
   в `analytics.py`, иначе они попадут в «НЕ КЛАССИФИЦИРОВАНО».

## 7. Проверка что всё работает

После запуска программы открой лист `01_Месячная_статистика` и просуммируй
колонку **«Итого по оплате + внешние, тыс. руб.»**. Должно получиться
значение близкое к `total_with_prog / 1000` из `verified_figures.json`
(в пределах 1–2%). Индикатор расхождения (🟢🟡🔴) в GUI после запуска
анализа показывает то же самое без ручного подсчёта.

Если расхождение больше 5% — что-то не так:
- проверь лог на строку «Внешние доходы подгружены: XXX тыс. руб.» и
  «Верифицированные цифры подгружены из verified_figures.json»
- проверь что дата оплаты у большинства заказов распознана
- проверь что `_год` в `external_income.json` и `verified_figures.json`
  совпадает с годом, который анализируешь (при несовпадении программа
  сама выведет предупреждение в лог)

## 8. Что НЕ считается с внешними доходами

Эти разрезы считаются **только по CRM** (во внешних данных нет клиентов,
менеджеров, отраслей):

- `02_Топ_клиентов`, `03_Топ_менеджеров`, `04_Отрасли`, `04а_Номенклатура`
- `07_RFM_все`, `08_RFM_сегменты`, `09_RFM_не_топ`
- `10_Распределение_заказов`

Поэтому если считать долю топ-клиента от «полной» годовой выручки, нужно
делить сумму клиента на верифицированный годовой итог (`total_with_prog`),
а не на сумму топа клиентов. Этот расчёт делается **руками в презентации**,
не в программе.

## 9. Что уже сделано и что можно улучшить дальше

Более ранняя версия этого документа предлагала список доработок GUI —
все они реализованы: переключатель даты (заказ/оплата), формы
редактирования `external_income.json` и `verified_figures.json`,
индикатор расхождения, сравнение периодов, вкладка наблюдателя за папкой.

Открытые направления:

- **`dohody_import.py` не обновляет `verified_figures.json`** — годовые
  итоги по-прежнему вписываются вручную после закрытия года бухгалтерией
  (см. §6, шаг 3). Это осознанное решение (см. §3), но при желании можно
  добавить режим «предварительный расчёт» из мастер-файла с явной пометкой
  «неподтверждено».
- **Сверка CRM-строк не автоматизирована.** Импортёр показывает
  бухгалтерские цифры по строкам, которые есть в CRM (реклама, IC-доходы),
  только для визуального сравнения — не сверяет их с фактической выгрузкой
  CRM за тот же период и не считает расхождение в %.
- **Автообновление** (`watcher.py`) отслеживает папку и запускает анализ
  по `.xlsx` заказов; на «Доходы ГГГГ.xlsx» он не реагирует — импорт
  мастер-файла бухгалтерии всегда ручной шаг.

## 10. Краткая шпаргалка

**Что должно совпадать:**
- «Итого по оплате + внешние» за год ≈ `total_with_prog` из `verified_figures.json` (±1–2%)
- «Выручка по дате оплаты» за год ≈ `total_with_barter_no_prog` (±1–2%)

**При переходе на новый год:**
1. GUI **⚙ Импорт Доходы.xlsx** → новый мастер-файл → «Применить»
2. Дополнить `RAW_LABEL_MAP` / `ACCOUNTING_ROWS`, если есть несопоставленные строки
3. После закрытия года — вписать 5 полей в **⚙ Верифицированные цифры**
4. Проверить новые проекты CRM в `PROJECT_GROUP_MAP`

**Если что-то не бьётся:**
- Проверь лог на «Внешние доходы подгружены…» и «Верифицированные цифры подгружены…»
- Открой `01_Месячная_статистика` и сравни колонки
- Погрешность 1–5% — норма (разная методология CRM и бухгалтерии)
- Погрешность 10%+ — что-то сломано, ищи причину (несовпадение `_год`, незаполненные месяцы, несопоставленные строки в импорте)
